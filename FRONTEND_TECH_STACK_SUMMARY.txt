┌─────────────────────────────────────────────────────────────────────────────┐
│ 2. STATE MANAGEMENT                                                          │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                               │
│ ► Zustand v4.4.7 (PRIMARY)                                                  │
│   ├─ Minimal boilerplate (no reducers, dispatchers)                         │
│   ├─ ~2KB bundle size (vs Redux ~50KB)                                      │
│   ├─ Direct hook access: useAuthStore()                                     │
│   ├─ Persistence middleware: localStorage auto-sync                         │
│   └─ TypeScript-first design                                                │
│                                                                               │
│ Store Example:                                                               │
│   • authStore.ts - Authentication state (user, isAuthenticated)            │
│   • Stores state in localStorage as 'auth-storage'                          │
│                                                                               │
│ Why NOT Redux?      → Too verbose for small/medium apps                    │
│ Why NOT MobX?       → Zustand's immutability is clearer                    │
│ Why NOT Context?    → Zustand has built-in persistence + devtools          │
│                                                                               │
└─────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────────┐
│ 3. HTTP CLIENT & API                                                         │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                               │
│ ► Axios v1.6.5 (PRIMARY)                                                    │
│   ├─ Request interceptors: Auto-inject Bearer token                         │
│   ├─ Response interceptors: Global error handling (401 cleanup)             │
│   ├─ Per-request timeout: 3min for evaluation endpoints                     │
│   ├─ Automatic token injection from localStorage                            │
│   └─ Double-header strategy: Authorization + X-Auth-Token                  │
│                                                                               │
│ ► Service Layer (encapsulation)                                             │
│   ├─ predictionService - Prediction API (getPredictionList, etc.)          │
│   └─ Future services: resumeService, interviewService                       │
│                                                                               │
│ ► React Query v5.17.19 (INSTALLED, NOT YET USED)                           │
│   └─ Future migration path for caching + server state                      │
│                                                                               │
│ Request Flow:                                                                │
│   Component → Hook (useAuth) → Service → Axios Client → API                │
│                                            ↓                                  │
│                                     Interceptors:                            │
│                                     • Add token                              │
│                                     • Set timeout                            │
│                                     • Handle 401                             │
│                                                                               │
│ Why NOT Fetch API?  → No interceptor pattern, more verbose                 │
│ Why NOT SWR?        → Zustand + Axios is simpler for this scale            │
│ Why NOT tRPC?       → Backend uses REST, not RPC                           │
│                                                                               │
└─────────────────────────────────────────────────────────────────────────────┘

│ 9. ENVIRONMENT & CONFIGURATION                                               │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                               │
│ Environment Variables:                                                       │
│                                                                               │
│ NEXT_PUBLIC_API_BASE_URL=http://localhost:8000/api                          │
│   ├─ Sent to browser (client-side accessible)                               │
│   ├─ Used in: config/api.ts, services/api/client.ts                        │
│   └─ Fallback: /api (relative path)                                         │
│                                                                               │
│ INTERNAL_API_URL=http://localhost:8888                                      │
│   ├─ Server-side only (not sent to browser)                                │
│   ├─ Used in: next.config.js for API rewriting                             │
│   └─ Avoids CORS issues via transparent proxy                               │
│                                                                               │
│ API Rewriting (next.config.js):                                             │
│ /api/:path* → INTERNAL_API_URL/api/:path*                                   │
│                                                                               │
│ This allows:                                                                 │
│ • Frontend localhost:3000 → next.js rewrites to backend:8888               │
│ • Zero CORS configuration needed                                            │
│ • Token automatically added by axios interceptor                            │
│                                                                               │
└─────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────────┐
│ 10. SECURITY FEATURES IMPLEMENTED                                            │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                               │
│ ✓ JWT Token Management                                                       │
│   ├─ Stored in localStorage                                                 │
│   └─ Retrieved on each request                                              │
│                                                                               │
│ ✓ Bearer Token Injection                                                     │
│   └─ Automatically added to all protected endpoints                         │
│                                                                               │
│ ✓ Double Header Strategy                                                     │
│   ├─ Authorization: Bearer {token}                                          │
│   └─ X-Auth-Token: {token}  (fallback)                                      │
│                                                                               │
│ ✓ Auth-Free Route Detection                                                  │
│   ├─ /user/register - no token needed                                       │
│   ├─ /user/login - no token needed                                          │
│   └─ /user/logout - no token needed                                         │
│                                                                               │
│ ✓ 401 Response Handling                                                      │
│   └─ Automatic token cleanup on auth failure                                │
│                                                                               │
│ ✗ NOT Implemented (recommendations):                                         │
│   ├─ CSRF token handling                                                    │
│   ├─ HTTPOnly cookie storage (over localStorage)                            │
│   ├─ Content Security Policy headers                                        │
│   ├─ Request signature verification                                         │
│   └─ Rate limiting (client-side)                                            │
│                                                                               │
└─────────────────────────────────────────────────────────────────────────────┘
