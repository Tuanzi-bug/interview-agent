# 系统架构设计

**最后更新**: 2026-02-01  
**维护者**: 架构团队

## 概述

面试吧平台采用基于微服务的分层架构，充分利用 Hertz 框架的高性能 HTTP 服务能力和 Eino 框架的大模型应用开发优势。

## 微服务拆分

### 1. 用户服务 (User Service)

**职责**: 用户生命周期管理、认证、授权

**关键功能**:
- 用户注册和登录
- 微信/第三方登录集成
- 用户信息管理（头像、邮箱等）
- JWT 令牌生成和验证
- 权限管理

**技术栈**: Hertz, JWT, GORM, Redis

**API 端点**:
```
POST   /api/auth/register          # 用户注册
POST   /api/auth/login             # 用户登录
POST   /api/auth/login/wechat      # 微信登录
GET    /api/user/profile           # 获取用户信息
PUT    /api/user/profile           # 更新用户信息
POST   /api/user/logout            # 登出
```

### 2. 简历服务 (Resume Service)

**职责**: 简历管理、解析、AI 分析

**关键功能**:
- 简历上传和存储
- PDF 解析和文本提取
- 简历内容向量化
- 简历 QA（基于简历的问题回答）
- 简历押题（根据简历生成可能的面试题）

**技术栈**: Hertz, Eino Agent, PDF Parser, Milvus, GORM

**API 端点**:
```
POST   /api/resume/upload          # 上传简历
GET    /api/resume/list            # 获取简历列表
GET    /api/resume/{id}            # 获取简历详情
DELETE /api/resume/{id}            # 删除简历
POST   /api/resume/{id}/analyze    # AI 分析简历
POST   /api/resume/{id}/qa         # 简历问答
GET    /api/resume/{id}/predictions # 获取押题
```

### 3. 面试服务 (Interview Service)

**职责**: 面试流程管理、题库管理

**关键功能**:
- 创建面试任务（综合/专项）
- 生成动态面试题
- 记录用户答案
- 面试历史和统计
- 题库管理

**技术栈**: Hertz, GORM, Redis (session)

**API 端点**:
```
POST   /api/interview/create       # 创建面试
GET    /api/interview/{id}         # 获取面试信息
GET    /api/interview/{id}/question # 获取问题
POST   /api/interview/{id}/answer   # 提交答案
POST   /api/interview/{id}/submit   # 提交面试
GET    /api/interview/history       # 面试历史
```

### 4. AI 评估服务 (Evaluation Service)

**职责**: 答案评估、反馈生成、报告

**关键功能**:
- 实时答案评估
- 评分和反馈生成
- 错误点分析
- 改进建议
- 评估报告生成

**技术栈**: Hertz, Eino Chain, LLM (OpenAI/ARK), GORM

**API 端点**:
```
POST   /api/evaluate/answer        # 评估答案
GET    /api/evaluate/{id}/report   # 获取评估报告
GET    /api/interview/{id}/analysis # 综合分析
```

### 5. 向量检索服务 (Vector Search Service)

**职责**: 文档向量化、相似度检索

**关键功能**:
- 文档向量化（简历、题库等）
- 相似度检索
- 知识库管理
- 上下文检索（RAG）

**技术栈**: Milvus, Eino Embedding, GORM

**内部接口**:
```
InsertDocument(doc)           # 插入文档向量
SearchSimilar(query, top_k)   # 相似搜索
DeleteDocument(id)            # 删除文档
```

## 数据流

### 用户简历分析流程

```
1. 用户上传简历
   └→ Resume Service 接收
      └→ PDF Parser 解析文档
         └→ 文本存储到 MySQL
         └→ 向量化存储到 Milvus
         └→ 返回上传成功

2. 用户请求 AI 分析
   └→ Resume Service 调用
      └→ Resume Analyzer Agent (Eino)
         └→ 从 Milvus 检索简历内容
         └→ 调用 LLM 进行分析
         └→ 生成分析结果
         └→ 存储分析报告到 MySQL
         └→ 返回分析结果
```

### 面试答案评估流程

```
1. 用户提交答案
   └→ Interview Service 接收
      └→ 存储答案到 MySQL
      └→ 触发评估异步任务

2. 异步评估任务
   └→ Evaluation Service
      └→ Evaluator Agent (Eino)
         └→ 从 MySQL 获取问题和答案
         └→ 从 Milvus 检索相关知识
         └→ 调用 LLM 进行评估
         └→ 生成评分和反馈
         └→ 存储评估结果到 MySQL
         └→ 推送通知给用户
```

## 技术决策

### 1. 为什么采用微服务架构？

✅ **独立部署**: 各服务可独立扩展和更新  
✅ **技术多样性**: 不同服务可选择最优技术  
✅ **故障隔离**: 单个服务故障不影响整体  
✅ **团队独立性**: 不同团队可独立开发  

### 2. 为什么使用 Hertz 作为 Web 框架？

✅ **高性能**: 基准测试优于主流框架  
✅ **字节验证**: 字节跳动内部大规模使用  
✅ **易用性**: Go 标准库风格 API  
✅ **生态完整**: 与 Eino、中间件等兼容  

### 3. 为什么使用 Eino 做 AI 应用开发？

✅ **专业设计**: 为大模型应用优化  
✅ **编排能力**: 图编排引擎强大  
✅ **流式处理**: 原生支持流式输出  
✅ **组件化**: 易于复用和扩展  

### 4. 为什么使用 MySQL + Redis + Milvus 的三层数据存储？

✅ **MySQL**: 结构化业务数据，支持复杂查询和 ACID 事务  
✅ **Redis**: 会话、缓存、临时数据，高性能  
✅ **Milvus**: 向量搜索，支持 RAG 和相似度匹配  

## 扩展性设计

### 水平扩展

**无状态设计**: 所有服务都是无状态的
- 支持多实例部署
- 通过负载均衡器分发请求
- 会话数据存储在 Redis

**数据库分片**: 
- 用户数据可按 user_id 分片
- 面试数据可按创建时间分片

### 性能优化

**缓存策略**:
- Redis 缓存热数据
- 用户信息缓存
- 题库缓存

**异步处理**:
- 使用消息队列处理耗时任务
- 评估报告生成异步化
- 向量化异步进行

## 安全性设计

### 认证与授权
- JWT 令牌认证
- 基于角色的访问控制 (RBAC)
- API 密钥管理

### 数据安全
- HTTPS 传输加密
- 敏感数据加密存储
- SQL 注入防护 (GORM)
- API 速率限制

### 日志和监控
- 请求日志记录
- 错误追踪和告警
- 性能指标收集

## 常见模式

### 模式 1: 异步处理 (使用消息队列)

**场景**: 评估报告生成、向量化处理

```go
// 提交评估任务
resp := EvaluateAnswer(answer)  // 立即返回任务 ID

// 异步处理
go func() {
    result := DoEvaluation(answer)
    StoreResult(result)
    NotifyUser(user_id, result)
}()
```

### 模式 2: Agent 链式调用

**场景**: 复杂的 AI 任务

```go
// 简历分析 Agent
analyzer := NewResumeAnalyzerAgent(llm)
result := analyzer.Analyze(resume)
// 内部会自动调用多个工具和 LLM
```

### 模式 3: 向量检索增强

**场景**: RAG 上下文检索

```go
// 检索相关上下文
context := vectorSearch.SearchSimilar(question)

// 使用上下文增强 LLM 提示
enhanced_prompt := AppendContext(prompt, context)

// 调用 LLM
response := llm.Call(enhanced_prompt)
```
