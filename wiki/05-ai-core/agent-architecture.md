# 智能体架构

> 深入理解系统的智能体设计和实现

## 🤖 智能体总览

本系统采用多智能体协作架构，不同性格和功能的智能体各司其职，共同完成面试全流程。

### 系统中的智能体

| 智能体 | 位置 | 职责 | 输入 | 输出 |
|--------|------|------|------|------|
| **面试智能体** | `agent/interview/` | 模拟真实面试官，进行多轮技术或综合面试 | 用户回答、简历信息 | 面试问题、追问、反馈 |
| **简历分析智能体** | `agent/resume/` | 解析 PDF 简历，提取结构化信息 | PDF 文件路径 | 结构化 JSON 数据 (UserInfo, Education, WorkExp) |
| **评估智能体** | `agent/record_evaluation/` | 分析面试全过程，生成详细评估报告 | 完整面试记录 (Mianshi Info) | JSON 评估报告 (维度评分、评语) |
| **预测智能体** | `agent/prediction/` | 基于简历预测可能问到的面试题 | 简历信息 | 5 道预测题目 (JSON) |

## 🧩 关键设计模式

1. **角色扮演 (Role Playing)**: 每个 Agent 都有明确的 Persona，如"经验丰富的校招面试官"。
2. **工具增强 (Tool Augmented)**: Agent 能够调用工具来获取上下文（如简历、面试记录）。
3. **结构化输出 (Structured Output)**: 关键 Agent（简历解析、评估、押题）被要求严格输出 JSON 格式，便于系统处理。
4. **上下文管理**: 利用 Eino 框架管理多轮对话的 Memory。
